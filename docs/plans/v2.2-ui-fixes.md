# RSS Widget v2.2 — UI Fixes Plan

Authored by the planner agent. Frozen decisions (D1-D10) and verified facts
(1-11) come from the task brief and are not re-litigated here. Do not
contradict `docs/plans/v2-contract.md` (item shape, id precedence, state
keys are unchanged by this work).

## Scope

Fix five defects in `DankRssWidget.qml` and `FeedParser.js`:

1. Bookmark button unclickable (`enabled: opacity > 0` trap).
2. Row click can un-read an already-read item instead of always opening it.
3. Links never open once an item has been read before (stale branch logic).
4. Filter-chip / mark-all row overflows and gets clipped at narrow widths.
5. Feed links containing `&amp;` are broken (never HTML-entity-decoded).

Plus two smaller additions: a read/unread toggle control (D2), and gated
keyboard focus for the search field (D8).

### Non-goals

- No redesign of the settings panel, feed list model, or persistence layer.
- No new widget dimensions (`minWidth`/`minHeight` stay default 100x100).
- No switch to `DankButtonGroup`/`DankTabBar` for the filter chips (too tall).
- No QML execution/testing in this repo — no `qml`, `qs`, or `quickshell`
  binary is to be launched. All QML changes are review + live-verified only.

## Delegate restructure (D1-D6, D10)

Child declaration order inside the delegate `Rectangle` matters: the
whole-row `MouseArea` must be declared **before** `itemColumn` so the two
buttons (declared later, inside `itemColumn`) paint on top and receive
their clicks — no `z` needed (fact 2). The row `MouseArea`'s hit area is
then shrunk with `anchors.rightMargin` so it never physically overlaps the
two controls, which are the last two visible children in `itemColumn`
(after the thumbnail, which is decorative and needs no exclusion since the
row click over it is fine).

```qml
delegate: Rectangle {
    id: itemDelegate
    readonly property bool isRead: root.readMap[model.itemId] === true
    readonly property bool isBookmarked: ReaderState.isBookmarked(root.bookmarkMap, model.itemId)

    // Sizing contract for the two trailing DankActionButtons, shared by
    // the row MouseArea's rightMargin and (if ever needed) by layout math.
    readonly property int controlSize: 22
    readonly property int controlsRowWidth: controlSize * 2 + Theme.spacingS

    width: feedListView.width
    height: itemColumn.implicitHeight + Theme.spacingS * 2
    radius: root.viewMode === "compact" ? 0 : Theme.cornerRadius
    opacity: isRead ? 0.5 : 1.0
    color: itemMouseArea.containsMouse ? Theme.withAlpha(Theme.primary, 0.08) : "transparent"

    Behavior on color { ColorAnimation { duration: Theme.shortDuration } }
    Behavior on opacity { NumberAnimation { duration: Theme.shortDuration } }

    // Whole-row MouseArea declared FIRST: later children (the two
    // DankActionButtons) are visually on top and get their own clicks;
    // this MouseArea's hit area is shrunk so it never overlaps them.
    MouseArea {
        id: itemMouseArea
        anchors.fill: parent
        anchors.rightMargin: (root.viewMode === "compact" ? Theme.spacingXS : Theme.spacingS)
            + itemDelegate.controlsRowWidth
        hoverEnabled: true
        cursorShape: Qt.PointingHandCursor
        onClicked: {
            // D1: row click ALWAYS opens + marks read. Never un-reads.
            var id = model.itemId;
            if (!id) return;
            root.markRead(id);
            if (root.openInBrowser && model.link) {
                if (!Qt.openUrlExternally(model.link)) {
                    ToastService.showError("Could not open link", model.link);
                }
            }
        }
    }

    RowLayout {
        id: itemColumn
        // No z needed: MouseArea above is declared first, so this paints
        // on top naturally, and its rightMargin excludes the buttons below.
        anchors.fill: parent
        anchors.margins: root.viewMode === "compact" ? Theme.spacingXS : Theme.spacingS
        spacing: Theme.spacingS

        // Text content (unchanged from current implementation)
        ColumnLayout {
            Layout.fillWidth: true
            spacing: root.viewMode === "compact" ? 0 : 2
            // ... source/title row, description, date — unchanged ...
        }

        // Thumbnail (hidden in compact mode) — unchanged, still decorative,
        // no MouseArea of its own; row click over it is fine and expected.
        Rectangle {
            id: thumbRect
            visible: root.viewMode !== "compact" && root.showImages
                && (model.imageUrl || "") !== "" && thumbImage.status !== Image.Error
            Layout.preferredWidth: 48
            Layout.preferredHeight: 48
            Layout.alignment: Qt.AlignVCenter
            // ... unchanged ...
        }

        // D2: read/unread toggle. Always enabled, always hittable.
        DankActionButton {
            iconName: itemDelegate.isRead ? "check_box" : "check_box_outline_blank"
            iconSize: 14
            buttonSize: itemDelegate.controlSize
            iconColor: itemDelegate.isRead ? Theme.primary : Theme.surfaceVariantText
            Layout.alignment: Qt.AlignVCenter
            opacity: (itemMouseArea.containsMouse || itemDelegate.isRead) ? 1.0 : 0.45
            enabled: true
            onClicked: itemDelegate.isRead ? root.markUnread(model.itemId) : root.markRead(model.itemId)

            Behavior on opacity { NumberAnimation { duration: Theme.shortDuration } }
        }

        // D3: bookmark toggle. Fixed `enabled: opacity > 0` trap (fact 1).
        DankActionButton {
            iconName: itemDelegate.isBookmarked ? "bookmark" : "bookmark_border"
            iconSize: 14
            buttonSize: itemDelegate.controlSize
            iconColor: itemDelegate.isBookmarked ? Theme.primary : Theme.surfaceVariantText
            Layout.alignment: Qt.AlignVCenter
            opacity: (itemMouseArea.containsMouse || itemDelegate.isBookmarked) ? 1.0 : 0.45
            enabled: true
            onClicked: root.toggleBookmark(model.itemId)

            Behavior on opacity { NumberAnimation { duration: Theme.shortDuration } }
        }
    }
}
```

Notes:

- `controlsRowWidth` is derived (`2 * controlSize + Theme.spacingS`), not a
  magic number — the spacing term matches `itemColumn.spacing`, the only
  gap between the two buttons since the thumbnail is excluded from layout
  when invisible (Qt Quick Layouts drop invisible children automatically,
  already relied on by the existing compact-mode thumbnail).
- D4 (idle opacity ~0.45, 1.0 on hover-or-active) applies identically to
  both controls; the exact idle value is a judgment call — 0.45 mirrors the
  0.5 "read" row-opacity already used elsewhere in this file, so it is
  visually consistent. The executor may adjust by a few hundredths if it
  looks wrong live, but must not go back to `opacity: 0`.
- **Compact mode (D10):** both controls are children of the same
  `itemColumn` RowLayout regardless of `viewMode`; only the thumbnail and
  description/date `Text` items become `visible: false` in compact mode.
  Since `controlsRowWidth` does not depend on `viewMode`, the row
  MouseArea's `rightMargin` correctly excludes both controls in both modes.
  No separate compact-mode code path is needed for the buttons themselves.
- `Qt.openUrlExternally` replaces `Quickshell.execDetached(["xdg-open", ...])`
  (fact 8, D6) so failures are visible via `ToastService.showError`, which is
  already imported via `qs.Services` per existing usage elsewhere in this
  file — confirm the import is present; if not, add
  `import qs.Services` is already at line 7, so `ToastService` is available
  without further imports (verify at implementation time by checking other
  `ToastService.*` call sites in this file, or that the singleton is
  auto-registered like other DMS services).
- Delete the two old comments ("Above itemMouseArea so the bookmark button
  gets its clicks..." and "Held at zero opacity rather than hidden...") —
  both describe the mechanism this plan replaces.

## Action-row layout plan (D9)

Target: the actions bar (filter chips + spacer + search toggle + mark-all)
must degrade from 680px down toward the 100px floor without the trailing
child being clipped by the ancestor's `clip: true`. Convert every plain
`width:` on a `RowLayout` child to a `Layout.*` property (fact 5 — only
`Layout.fillWidth`/`Layout.preferredWidth`/`Layout.minimumWidth` participate
in the compression contract).

Per-child changes to the `RowLayout` at lines 592-703:

| Child | Current | New |
|---|---|---|
| Each filter-chip `Rectangle` (Repeater delegate) | `width: filterLabel.implicitWidth + Theme.spacingS` | `Layout.preferredWidth: filterLabel.implicitWidth + Theme.spacingS` (same formula, now a layout property) |
| Spacer `Item` | `Layout.fillWidth: true` (unchanged) | unchanged — this is the primary shrink absorber, already correct |
| Search `DankActionButton` | implicit `buttonSize: 22` sizing, no Layout property | add `Layout.preferredWidth: 22` and `Layout.preferredHeight: 22` so it never shrinks — it is a core, always-needed control |
| Mark-all `Rectangle` | `width: allReadRow.implicitWidth + Theme.spacingS * 2` | `Layout.preferredWidth: allReadRow.implicitWidth + Theme.spacingS * 2`, plus `Layout.minimumWidth: 22 + Theme.spacingS * 2` (icon-only floor), plus `visible: root.widgetWidth >= 160` |

Degradation strategy, by width:

- **680px (default saved size):** everything fits with room to spare; no
  visible change from today except the fixed bookmark bug and the new
  read-toggle control appearing next to it.
- **~300px:** the existing `visible: root.widgetWidth >= 300` on the
  "Mark all read/unread" text label (line 684, unchanged) drops the label,
  shrinking the mark-all `Rectangle` to icon-only via its own
  `implicitWidth` recompute — this already worked before and keeps working
  now that the width is a `Layout.preferredWidth` instead of a plain width.
  The spacer `Item` absorbs the freed/needed space.
- **~160-220px:** filter chips (their own preferred widths are unelided
  text, e.g. "Unread (3)") may now consume most of the available width.
  The spacer collapses fully to 0 first; once it is at 0 and space is still
  short, the mark-all control's new `visible: root.widgetWidth >= 160`
  removes it entirely rather than letting it clip — this is the actual fix
  for "trailing item overflows and gets clipped" (fact 5), since the
  previously-unbounded trailing `Rectangle` is now the first thing to
  disappear, not the thing that gets cut off mid-render.
- **100px floor (fact 7, default `minWidth`):** three filter chips alone
  (`"All"`, `"Unread (N)"`, `"Saved (N)"`) can plausibly exceed 100px on
  their own once counts are double digits. This plan does **not** attempt
  to abbreviate or wrap the chips — that would require either wrapping
  (`Flow`) or per-chip eliding, both out of scope per the "no
  DankButtonGroup/DankTabBar" constraint and not requested by the frozen
  decisions. **Accepted limitation, flagged explicitly:** at the extreme
  100px floor the filter-chip row may still be visually cramped or clipped
  by the ancestor's `clip: true`; what this task guarantees is that the
  *trailing* item (mark-all) is never the clipped one — it is hidden
  cleanly at 160px before that can happen, and the search toggle (a fixed
  22px control, core functionality) is always preserved. If the user finds
  100px-wide chip clipping unacceptable in live testing, that is a follow-up
  ticket, not part of this plan.

## Parser change (D7)

**Decision: reuse `cleanText()` for the link field. Do not write a
narrower decoder.**

Reasoning: `cleanText()` does two things — (a) decode `&amp; &lt; &gt;
&quot; &#39; &apos;` and numeric character references, and (b) collapse
runs of whitespace to a single space and trim. For a URL:

- (a) is exactly correct and required — an XML/RSS document legally
  represents a literal `&` in an attribute-less text node as `&amp;`, and a
  conforming URL never contains a literal `<`, `>`, or `"`, so decoding
  those entities back is safe and never destructive.
- (b) is a no-op for any well-formed URL, since URLs cannot contain literal
  whitespace. If a malformed feed injected whitespace into a link (e.g. a
  line-wrapped `<link>` element), collapsing it to a single space is no
  worse than the current behavior (which leaves the raw whitespace/newlines
  in place) and arguably better. There is no case where cleanText's
  whitespace handling corrupts a link that would otherwise have worked.

A narrower "entity-decode only" function would duplicate `cleanText`'s
entity table for zero behavioral benefit here, and CONTRACT 1 already
freezes `cleanText` as a general-purpose export — introducing a second,
overlapping decode function would be redundant and a maintenance burden.

**Exact change**, both in `parseRssFeed` (FeedParser.js:115-146) and
`parseAtomFeed` (FeedParser.js:178-209):

```js
// parseRssFeed — replace:
var itemLink = link || "";
// with:
var itemLink = link ? cleanText(link) : "";
```

```js
// parseAtomFeed — replace:
var link = pickAtomLink(block);
// with (decode after picking, so pickAtomLink's own rel/href parsing sees
// raw attribute text, unaffected):
var link = cleanText(pickAtomLink(block));
```

Do **not** change `makeItemId`'s call site — it already receives
`itemLink`/`link` as a parameter, so it automatically gets the decoded
value once the two assignments above change, and CONTRACT 3's id
precedence (`"l:" + trimmed link`) is unaffected in shape, only in the
value being trimmed of entities too (which is the correct, non-broken
value — a bare regression fix, not a contract change).

## Risks

- **D8 (`acceptsKeyboardFocus: root.searchActive`) has no precedent in this
  DMS build** (per the task brief: "NO other DMS widget declares it —
  this is unproven"). It relies on a live binding in
  `DesktopPluginWrapper.qml:214` behaving as documented from fact 4, but
  that path has never been exercised by a real plugin. If it does not
  work, the search field may still be usable via mouse-focus-follows or
  may simply never receive key events — this can only be resolved by the
  live checklist's last item, not by static review.
- **100px-floor chip clipping is explicitly NOT fully solved** (see
  "Action-row layout plan" above) — flagged rather than silently
  papered over.
- **`ToastService` availability**: this plan assumes `ToastService` is
  reachable as a bare singleton identifier in `DankRssWidget.qml` (as it
  is used in other DMS widgets per CONTRACT verified facts). The executor
  must confirm this resolves without an explicit import before relying on
  it in the `onClicked` handler — if it does not resolve, an explicit
  `import qs.Services` addition (already present at line 7 per current
  file) should already cover it, but this needs a real compile/parse check
  at review time since this plan cannot execute QML.
- **Idle opacity value (0.45)** is a judgment call, not directly specified
  by the frozen decisions beyond "idle opacity ~0.45" — cosmetic, low risk,
  adjustable by the executor without violating any contract.

## Something I want to flag, not silently deviate from

Frozen decision D6 says "If it returns false, surface
`ToastService.showError(...)`" — the exact `ToastService` call signature
per CONTRACT verified facts is
`ToastService.showInfo/showWarning/showError(msg, details, cmd, cat)`
(4 params, with `details`/`cmd`/`cat` presumably optional). This plan uses
`ToastService.showError("Could not open link", model.link)` — passing the
link as the `details` arg. If `showError`'s signature requires all 4
params or treats a 2nd string arg differently, the executor should check
the JSDoc/usage at another DMS call site before landing this line; this
plan does not treat that as a design decision worth blocking on, just a
call-signature detail to verify at implementation time.
